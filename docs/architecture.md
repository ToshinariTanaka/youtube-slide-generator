# アーキテクチャ

## 方針

このアプリは、フレームワークを使わない静的Webアプリとして構成しています。人間があとからHTML/CSS/JavaScriptを直接読み、必要に応じて修正できることを優先しています。

## 主要ファイル

- `index.html`
  - 空行分割用の台本入力、スライド分解テキスト入力、画像アップロード、生成ボタン、編集可能なプレビュー領域を定義します。
  - PNG出力のために `html2canvas` をCDNから読み込みます。
- `style.css`
  - デザイン設定をCSS変数に集約します。
  - アプリ全体のUI、編集フォーム、操作ボタン、3種類のスライドテンプレートを定義します。
- `script.js`
  - 台本の段落分割、スライド分解テキスト解析、スライドデータ作成、生成後編集、DOM生成、PNG保存を担当します。

## データの流れ

### 空行分割方式

1. ユーザーが「説明文・台本（空行ごとに分割）」へ説明文を入力します。
2. JavaScriptが説明文を空行で分割します。
3. 1段落目をタイトルスライド、2段落目以降を説明スライドとして扱います。
4. 画像が割り当てられた説明スライドは、画像＋説明スライドになります。

### スライド分解テキスト方式

1. ユーザーが「スライド分解テキスト」へ `--- slide 1`、`タイトル：`、`本文：` 形式のテキストを貼り付けます。
2. JavaScriptが区切り行とタイトル・本文ラベルを解析します。
3. スライド番号が指定されている場合は、番号順に並べます。
4. ラベルが崩れている場合でも、先頭行をタイトル、残りを本文として可能な範囲でスライド化します。
5. 1枚目をタイトルスライド、2枚目以降を説明スライドまたは画像＋説明スライドとして扱います。

### 生成後編集とPNG出力

1. 生成されたスライドデータは `currentSlideDataList` に保持します。
2. 各スライドカードに、タイトル編集、本文編集、削除、複製、上へ、下へ、PNG保存のUIを表示します。
3. タイトル・本文の入力変更は、保持データとスライドプレビューのDOMへ即時反映します。
4. 削除・複製・順番変更は、保持データを更新してプレビュー全体を再描画します。
5. `html2canvas` は編集UIではなく `.slide` 要素だけをcanvas化するため、編集後のスライド見た目だけをPNG保存します。

## テンプレート

- タイトルスライド: 動画冒頭のテーマ表示用。
- 説明スライド: 本文中心の解説用。
- 画像＋説明スライド: スキャン画像と解説文を並べる教材用。

## 注意点

- 現時点ではバックエンドや保存用データベースはありません。
- 現時点ではOpenAI APIなどの外部AI連携はありません。ChatGPTなどで作成した分解済みテキストを貼り付ける前提です。
- PNG出力はブラウザ機能と `html2canvas` に依存します。
- 連番PNGの一括保存は、ブラウザのダウンロード制限に影響される可能性があります。
- 生成後編集はブラウザ上の一時状態です。ページを再読み込みすると編集内容は消えます。
