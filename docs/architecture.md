# アーキテクチャ

## 方針

このアプリは、フレームワークを使わない静的Webアプリとして構成しています。人間があとからHTML/CSS/JavaScriptを直接読み、必要に応じて修正できることを優先しています。

## 主要ファイル

- `index.html`
  - 入力フォーム、画像アップロード、生成ボタン、プレビュー領域を定義します。
  - PNG出力のために `html2canvas` をCDNから読み込みます。
- `style.css`
  - デザイン設定をCSS変数に集約します。
  - アプリ全体のUIと、3種類のスライドテンプレートを定義します。
- `script.js`
  - 台本の段落分割、スライドデータ作成、DOM生成、PNG保存を担当します。

## データの流れ

1. ユーザーが説明文を入力します。
2. ユーザーが必要に応じてスキャン画像をアップロードします。
3. JavaScriptが説明文を空行で分割します。
4. 1段落目をタイトルスライド、2段落目以降を説明スライドとして扱います。
5. 画像が割り当てられた説明スライドは、画像＋説明スライドになります。
6. 生成したスライドDOMをブラウザ上に表示します。
7. `html2canvas` でスライドDOMをcanvas化し、PNGとして保存します。

## テンプレート

- タイトルスライド: 動画冒頭のテーマ表示用。
- 説明スライド: 本文中心の解説用。
- 画像＋説明スライド: スキャン画像と解説文を並べる教材用。

## 注意点

- 現時点ではバックエンドや保存用データベースはありません。
- PNG出力はブラウザ機能と `html2canvas` に依存します。
- 連番PNGの一括保存は、ブラウザのダウンロード制限に影響される可能性があります。
